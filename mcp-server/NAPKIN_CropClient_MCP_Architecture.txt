NAPKIN: CropClient MCP Architecture
====================================
Date: Jan 1, 2026
Steve's Vision: Everything is a Prompt, Allware not Software

THE BIG PICTURE
---------------
MCP Tools = Foundation (universal interface, data-source agnostic)
Data Sources = Swap underneath (JSON, API, SQLite, SQL Server, Mongo)
User Switcher = Different credentials per user per data source
Domain Switcher = One dropdown changes everything

TWO WORLDS
----------
1. DASHBOARD WORLD (Grid/CRUD)
   - Always JSON in the grid (fast, offline-capable)
   - Local JavaScript execution for display
   - status=-1 means "queued for sync"
   - Works offline OR online

2. API WORLD (External Systems)  
   - CropManage API, SQLite, SQL Server, Mongo
   - MCP tokens execute server-side
   - Test localhost → Deploy cropclient.io
   - Middleware, single sign-on

THE 4 CRUD TOOLS (Dashboard MCP Server)
----------------------------------------
create_next_irrigation - Create next irrigation event
reset_table           - Reset grid to original/cached state
read_meter            - Prepare for meter reading entry
update_record         - Update manager hours & water applied

These tools work regardless of backend.
Backend selected = where data comes from.

DATA SOURCE SWITCHER
--------------------
Dropdown with options:
- Demo (Static JSON)     → Embedded data, no server
- Demo (Live JSON)       → localhost:3100, no auth
- CropManage API         → api.dev.cropmanage.ucanr.edu, needs auth
- CropClient.io (Prod)   → cropclient.io/api, needs auth
- SQLite (Local)         → localhost:3101, no auth
- SQL Server             → localhost:3102, needs auth
- MongoDB                → localhost:3103, needs auth

USER SWITCHER
-------------
Dropdown: Steve, Michael, Sean, etc.
Each user has credentials per data source:
  steve → cropmanage-api → steve@cropclient.com / ***
  steve → cropclient-io  → steve / ***
  steve → sqlserver      → sa / ***

Credentials cached per user/source combo.

THE QUEUE (Status System)
--------------------------
Grid records have status field:
  status: -1  = Queued (needs sync to external system)
  status: 1   = Synced (posted/updated successfully)
  status: 0   = Original (from external source)

Token "Post all queued records" → finds status=-1 → posts to selected data source

TWO CMD WINDOWS
---------------
Window 1: Dashboard MCP Server (port 3100)
  - 4 CRUD tools (MCP stdio)
  - HTTP bridge (Express on 3100)
  - Data source router
  - Always running

Window 2: API MCP Server (port 3101)
  - 7 CropManage API tools
  - Pure MCP stdio
  - Runs when needed for external data

DEPLOYMENT PATTERN
------------------
1. Build locally (localhost testing)
2. Test tokens execute correctly
3. Deploy to cropclient.io (production)
4. Same domain = NO CORS issues
5. Users access via cropclient.io (all scripts server-side)

KEY PRINCIPLES
--------------
1. JSON is the water of IT life (always cached, always available)
2. MCP tools = universal interface (backend swaps underneath)
3. If it's not broke, don't fix it (working code stays working)
4. Injected code, not dynamic requires (fast, portable, testable)
5. Natural language routes to tools (Everything is a Prompt)
